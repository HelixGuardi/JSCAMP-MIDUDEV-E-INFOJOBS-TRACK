**Gotcha / nota:**

| Caso | Qué devuelve |
| --- | --- |
| OK | stream de texto (`pipeTextStreamToResponse`). No es `{ summary }` |

### Rate limit con `express-rate-limit`

**Cuándo usarlo:** en la ruta que cobra tokens, no en todo el API de empleos.

**Código:**

```js
// modulo-09-Inteligencia-Artificial/backend/routes/ai.js
const aiRateLimiter = rateLimit({
  windowMs: 60 * 1000, // 1 minuto
  limit: 5, // 5 peticiones por IP por minuto
  message: {
    error: "Demasiadas solicitudes, por favor intenta de nuevo más tarde",
  },
  legacyHeaders: false,
  standardHeaders: "draft-8", // devuelve headers estándard RateLimit-*
});

export const aiRouter = Router();
aiRouter.use(aiRateLimiter);
```

```js
// modulo-09-Inteligencia-Artificial/backend/app.js
app.set("trust proxy", 1); // Si estás detrás de un proxy, como Nginx, Heroku, Cloudflare, Vercel... esto es importante para que el rate limiter funcione correctamente con la IP del cliente real.
```

**Gotcha / nota:** 5 por IP por minuto, solo bajo `/ai`. No pasas `store`: el casero, en cambio, dice que es memoria. Sin `trust proxy`, detrás de Vercel/Nginx todas las IP pueden colapsar en la del proxy. El apunte 17 habla de 429, retries y backoff; eso no está implementado. El hook trata cualquier `!response.ok` igual (`"Error fetching summary"`), así que el usuario no ve el mensaje de “demasiadas solicitudes”.

### Rate limit casero (prototipo)

**Cuándo usarlo:** un demo en memoria, antes de meter la librería. No es el que protege el resumen.

**Código:**

```js
// modulo-09-Inteligencia-Artificial/examples/rate-limit.js
const WINDOW_MS = 60 * 1000 // 1 minuto
const MAX_REQUESTS = 30
const rateLimit = new Map()

export function rateLimitMiddleware (req, res, next) {
  const ip = req.ip
  const now = Date.now()
  const entry = rateLimit.get(ip)

  if (!entry || now - entry.start > WINDOW_MS) {
    rateLimit.set(ip, { start: now, count: 1 })
    return next()
  }

  if (entry.count >= MAX_REQUESTS) {
    return res.status(429).json({ error: 'Demasiadas peticiones. Intenta de nuevo más tarde.' })
  }

  entry.count++
  return next()
}
```

```js
// modulo-09-Inteligencia-Artificial/examples/app.js
app.get('/api', rateLimitMiddleware, (req, res) => {
  res.json({ status: 'ok', uptime: process.uptime(), timestamp: Date.now() })
})
```

**Gotcha / nota:** 30/min, solo en `GET /api`, `Map` por proceso. El `setInterval` que borra entradas expiradas no se limpia. No comparte estado entre instancias. `examples/app.js` no carga `.env` ni llama a ningún modelo.

## Parte C — Frontend de IA

### `useAISummary`

**Cuándo usarlo:** el resumen no se pide al montar la página. Lo dispara el click.

**Código:**

```jsx
// modulo-09-Inteligencia-Artificial/frontend/src/hooks/useAISummary.jsx
export function useAISummary(jobId) {
  const [summary, setSummary] = useState(null);
  const [loading, setLoading] = useState(false);
  const [error, setError] = useState(null);

  const generateSummary = async () => {
    setLoading(true);
    setError(null);
    setSummary("");

    try {
      const response = await fetch(`${API_URL}/ai/summary/${jobId}`);
      if (!response.ok) {
        throw new Error("Error fetching summary");
      }
      // ...lectura del stream
    } catch {
      setError(
        "Error al generar el resumen. Intentalo otra vez más tarde, gracias!💖",
      );
    } finally {
      setLoading(false);
    }
  };
```

**Gotcha / nota:** `API_URL` es `import.meta.env.VITE_API_URL`. No hay `useEffect` que llame solo. `loading` sigue en `true` hasta que el `while` termina, no solo hasta el primer byte. No cancelas el fetch anterior. No miras `response.body`.

### Consumir el stream

**Cuándo usarlo:** el backend ya no manda JSON. Lees chunks y los vas concatenando.

**Código:**

```jsx
// modulo-09-Inteligencia-Artificial/frontend/src/hooks/useAISummary.jsx
const reader = response.body.getReader();
const decoder = new TextDecoder();

while (true) {
  const { done, value } = await reader.read();
  if (done) break;

  const chunkText = decoder.decode(value, { stream: true });
  setSummary((prev) => prev + chunkText);
}
```

**Gotcha / nota:** `{ stream: true }` está en el hook; el apunte 19 decodifica sin ese segundo argumento (solo apunte). `setSummary("")` al empezar: `""` es falsy, así que hasta el primer chunk sigues viendo el botón “Generando resumen...”, no el bloque de markdown. Si falla después del primer chunk, `Detail` pinta `summary` y no llega al `error` (el `if (summary)` va primero).

### Tokens y coste al escribir el prompt

**Cuándo usarlo:** antes de alargar el system prompt o de pedir una salida larga. Te cobran entrada y salida por separado.

**Código:** solo apunte, no hay código. Apunte 03:

- El mismo texto no vale los mismos tokens en GPT, Gemini y Claude. No compares precios de modelos contando “palabras”.
- Inglés suele gastar menos que español (`"I am"` ≈ 1 token, `"yo soy"` ≈ 2, en el ejemplo del apunte).
- Ejemplo de tarifa del apunte, no de tu factura: ~1,7 $ por millón de tokens de entrada y ~14 $ por millón de salida.
- Por encima de un umbral (el apunte pone 200.000 tokens) el precio puede cambiar.
- Más tokens: más coste y más latencia. El apunte no nombra la herramienta de conteo (“existen herramientas oficiales”).

**Gotcha / nota:** tu prompt pide la respuesta en español y mete título, empresa, ubicación y `descripcion`. La salida es la parte cara del ejemplo (14 frente a 1,7). No hay un coste “por resumen típico” calculado en el módulo.

## Checklist para añadir IA a un proyecto web existente

1. **Clave solo en el backend.** `backend/.env` + `process.loadEnvFile()` en el proceso que llama al modelo. El frontend, como mucho, `VITE_API_URL`. Nunca `OPENAI_API_KEY` en cliente (apuntes 13, 14 y 16). Cuidado con el orden: un `import` que lea `process.env` al cargarse gana a `loadEnvFile()` escrito encima.

2. **SDK según la forma de la respuesta.** JSON cuando puedes esperar: cliente `openai` y `res.json({ summary })` (comentado). Stream cuando quieres ver el texto ya: `streamText` + `pipeTextStreamToResponse`. No mezcles los dos finales (`res.json` después de haber abierto el stream).

3. **Un endpoint tuyo delante del modelo.** Aquí `GET /ai/summary/:id`: el servidor busca la oferta y arma el prompt. El browser no habla con el proveedor.

4. **Rate limit en esa ruta.** `express-rate-limit` a 5/minuto por IP, más `trust proxy` si hay proxy. El `Map` de `examples/rate-limit.js` vale para un prototipo de un solo proceso (30/min), no para el resumen.

5. **UI: idle / stream / error.** Botón que llama a `generateSummary`. `loading` hasta que el reader acaba. Concatena chunks. El `""` inicial no cuenta como “ya hay resumen”. Si pintas `summary` antes que `error`, un fallo a mitad deja el texto parcial y esconde el mensaje.

6. **Markdown del stream con un renderer que aguante trozos.** En este módulo, `Streamdown` para el resumen. `snarkdown` + `dangerouslySetInnerHTML` se quedó para el cuerpo estático de la oferta, no para el stream.

7. **Coste.** No tienes cifra por llamada. Del apunte 03: la salida de ejemplo sale mucho más cara que la entrada (~14 $ vs ~1,7 $ por millón). Acota frases y no repitas en el prompt campos que no hagan falta. El rate limit es el freno que sí está en código.

8. **Cuándo no meterla** (sale de los apuntes, no de una regla de producto escrita):
   - La clave tendría que vivir en el frontend.
   - La acción es un loop, un duplicado o un refresh de un `GET` que ya cobra (apunte 17: cada request cuenta).
   - Es una duda puntual: chat o Ask, no un agente que se lee el repo (apuntes 04 y 05). Cada archivo leído suma contexto.
   - Solo necesitas instrucciones repetibles: skill, no MCP (apunte 08).
   - El material es de estudio y quieres citas a tus fuentes: NotebookLM, no un endpoint de producto (apunte 10).
   - El código no puede salir de la máquina: Ollama, no la API de pago (apunte 09), sabiendo el coste de RAM/GPU.
